# 記事の推敲と校正レビュー

`frontend/app/articles/` 配下のメディア記事を、2段階でチェックする。

1. **推敲(yomiyasu)**: メイン側で `yomiyasu` スキルを読み込み、記事の日本語を整える。
2. **校正(article-proofreader)**: サブエージェントで事実・データ整合性、日本語校正、AIっぽさ(humanizer-ja準拠)、構成、内部リンク健全性をチェックする。

推敲で文章が変わってから校正に入るので、順番は必ず 1 → 2。校正の後に本文を書き直したら、変えた段落だけでも 1 からやり直す。

## いつ使うか

- **記事を新規作成した後、および本文・数字を大幅に編集した後は必ず実行する**(公開前の最終チェック)。
- ユーザーが「記事を校正して」「記事をレビュー」「文章を読みやすくして」と依頼したとき。

## 手順

### 0. 対象を特定する

- 直前に作成・編集した記事があればそれを対象にする(`git status` / `git diff` で変更範囲を確認)。
- 指定があればそれに従う。
- 対象は本文の `page.tsx` だけでなく、`frontend/lib/articles.ts` の `title` / `description` と、`page.tsx` 内の OG 画像の `title` / `subtitle` も含める(検索結果とSNSに出る文章なので、本文と同じ基準で整える)。

### 1. yomiyasu で推敲する(メイン側で実施)

1. Skill ツールで `yomiyasu` を読み込む。ドメインは `essay`(メディア記事)、立場は原則「説明」として扱う。
2. 記事から**日本語の地の文だけ**を取り出す: リード文、見出し、段落、注記、表のキャプション、`articles.ts` の title/description。JSX の構造、`{}` 内の式、数値、固有名詞(大学名・大会名・種目名・選手名)、リンク先、`<Link>` のアンカーテキストに含まれる固有名詞は対象外。yomiyasu の「意味の保持」「情報の不増補」はそのまま適用し、数字や集計条件の説明は一字も変えない。
3. 取り出した地の文をスクラッチディレクトリにテキストで保存し、同梱スクリプトで静的検査と差分検査を回す:
   ```bash
   python3 ~/.claude/skills/yomiyasu/scripts/yomiyasu_lint.py <元の文.txt>
   python3 ~/.claude/skills/yomiyasu/scripts/yomiyasu_diff.py <元の文.txt> <書き直した文.txt> --stance=説明
   ```
   検出結果は候補として扱い、専門用語や評価を担う語は無理に言い換えない。修正は1回のみで、スクリプトを回し直す往復はしない。
4. yomiyasu の出力フォーマットのうち「変えたところ」「残したAIっぽいところ」「書き手に確かめたい点」をユーザーに提示する。「書き手に確かめたい点」がある箇所は、ユーザーの回答を待ってから本文に反映する。
5. 書き直した文を `page.tsx` / `articles.ts` に反映する。JSX の構造や式は動かさず、文字列だけを差し替える。

### 2. article-proofreader で校正する

1. Agent ツールで `subagent_type: "article-proofreader"` を起動する。プロンプトに以下を含める:
   - 対象記事のファイルパス(例: `frontend/app/articles/<slug>/page.tsx`)と、参照している lib(`articles.ts`, `results-data.ts`)。
   - 記事の狙い・データの集計条件(分かっていれば)。
   - 「実データを自分で再集計して本文の数値を検証すること」を明示的に指示する。
   - yomiyasu の推敲を済ませていることと、その「変えたところ」の要点(校正側が同じ箇所を逆戻しにしないため)。
2. サブエージェントの結果はユーザーに直接表示されないため、報告内容を要約せず**そのまま**ユーザーに提示する。
3. 「要修正」に挙がった事実誤り・データ不整合・誤字は、メイン側で修正案を確認のうえ実装する。「推奨」項目はユーザーの判断を仰ぐ。
4. 修正したら、ビルド確認と本番反映まで通常フローで行う。数値・データに関わる修正をした場合は、再度 2 で確認する。本文の段落を書き直した場合は 1 からやり直す。

## 注意

- 校正(2)はレビューのみを行い、サブエージェント側ではコードを変更しない。推敲(1)の反映と校正結果の実装はメイン側で行う。
- humanizer-ja と yomiyasu はどちらも「意味を変えない」が前提で、役割が違う。humanizer-ja は AIくさい定型表現の検出と人間らしい言い換え、yomiyasu は主述の対応・文のつながり・文末の立場・装飾記号の整理を担う。同じ箇所で言い換えの好みがぶつかったときは、記事の声として先に採用している humanizer-ja を優先する。
- SEO・拡散の観点は `marketing-review` スキル(marketer)が担当。役割が重複したら、事実正確性・日本語・読みやすさはこのスキル、検索流入・シェアは marketer に振り分ける。
