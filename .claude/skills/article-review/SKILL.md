# 記事校正レビュー

`frontend/app/articles/` 配下のメディア記事を、`article-proofreader` サブエージェントで校正する。事実・データ整合性、日本語校正、AIっぽさ(humanizer-ja準拠)、構成、内部リンク健全性をチェックする。

## いつ使うか

- **記事を新規作成した後、および本文・数字を大幅に編集した後は必ず実行する**(公開前の最終チェック)。
- ユーザーが「記事を校正して」「記事をレビュー」と依頼したとき。

## 手順

1. レビュー対象の記事ファイルを特定する。
   - 直前に作成・編集した記事があればそれを対象にする(`git status` / `git diff` で変更範囲を確認)。
   - 指定があればそれに従う。
2. Agent ツールで `subagent_type: "article-proofreader"` を起動する。プロンプトに以下を含める:
   - 対象記事のファイルパス(例: `frontend/app/articles/<slug>/page.tsx`)と、参照している lib(`articles.ts`, `results-data.ts`)。
   - 記事の狙い・データの集計条件(分かっていれば)。
   - 「実データを自分で再集計して本文の数値を検証すること」を明示的に指示する。
3. サブエージェントの結果はユーザーに直接表示されないため、報告内容を要約せず**そのまま**ユーザーに提示する。
4. 「要修正」に挙がった事実誤り・データ不整合・誤字は、メイン側で修正案を確認のうえ実装する。「推奨」項目はユーザーの判断を仰ぐ。
5. 修正したら、ビルド確認と本番反映まで通常フローで行う。数値・データに関わる修正をした場合は、再度このスキルで確認する。

## 注意

- レビューのみを行い、このスキル内(サブエージェント側)ではコードを変更しない。校正と実装は分離する。
- SEO・拡散の観点は `marketing-review` スキル(marketer)が担当。役割が重複したら、事実正確性・日本語・読みやすさは article-proofreader、検索流入・シェアは marketer に振り分ける。
