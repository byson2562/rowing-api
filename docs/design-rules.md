# レガッタナビ デザインルール

toC向けのメディア寄り(白地・墨色の文字・細い罫線・青はデータの色)を、参照サイトと公開デザインシステムを基準に成文化したもの。
UIを新規作成・変更するときは必ずこのルールに従う(適用は `.claude/skills/design-rules` スキル経由)。

方向性(2026-10-20 決定): **日経ビジュアルデータ寄り**。
白地に墨色の文字と細い罫線だけ。角丸・影・地色の箱は作らない。見出しは太字で言い切り、本文は灰色、図は青1色+灰青。結果は表より先に小さな図で見せる。
比較した3方向のモックは https://claude.ai/artifact/5SXru6wtgPLbPqCj1kgmLL に残っている。

参照基準:
- **日経ビジュアルデータ** … 版面・見出し・図の見せ方の手本(結論型の見出し、本文の上に置く小さな図、罫線だけの表)
- **デジタル庁デザインシステム** … 日本語タイポグラフィとアクセシビリティの数値基準
- **Vercel Geist** … 高密度データテーブル・空状態の見せ方
- (補助) SmartHR … UI文言のトーン

## 2. カラートークン(`frontend/app/globals.css` の `:root` が唯一の出典)

| 役割 | トークン | 値 | 用途 |
|---|---|---|---|
| 背景 | `--bg` | `#ffffff` | ページ地。**色付きの全面背景は禁止** |
| 面(弱) | `--surface-soft` | `#eef1f5` | 図のトラック・図の地。**箱の地には使わない** |
| 罫線 | `--border` | `#dcdcdc` | 標準ヘアライン、表の行 |
| 罫線(弱) | `--border-soft` | `#ececec` | 補助的な区切り |
| 罫線(強) | `--border-strong` | `#1f1f1f` | 表・図の上罫線 |
| 見出し・本文・リンク | `--text` / `rn-text` / `rn-link` / `rn-brand` | `#1f1f1f` | 墨色。リンクも墨色で、hoverで下線(本文中は常時下線) |
| 本文(記事・リード) | `--text-body` | `#3d3d3d` | 長文 |
| 説明 | `--muted` | `#5a5a5a` | 説明文・カードの本文(7.0:1) |
| メタ | `--meta` | `#6f6f6f` | 日付・ラベル・表ヘッダ(5.0:1) |
| データの青 | `--primary` | `#1d5fbf` | **図・1位・選択状態・フォーカスにだけ使う**。ボタンや見出しには使わない |
| 青(濃) | `--primary-dark` | `#174c99` | 図のhover |
| 灰青 | `--primary-soft` | `#b9c7dc` | 図の副系列、2〜3位 |
| (廃止) | `--accent` | `= --primary` | オレンジは廃止。旧 `bg-rn-accent` は青に落ちる。新規に使わない |

ルール:
- 新しい色を増やさない。必要になったらまずトークンで代替できないか検討し、増やす場合はここに追記+コントラスト検証。
- 意味色(フォームのエラー `#b42318` 等)はこの表の外。装飾には使わない。
- Tailwindでは `rn-*` トークンユーティリティ(`text-rn-meta` 等)を優先。arbitrary の固有色は書かない。

## 3. 形・深度

- **箱を作らない**: カード・パネル・枠付きの囲みは使わない。一覧は `border-b border-rn-border` の行、セクションは余白と見出しで区切る。
- **radius**: 入力・ボタン `rounded-rn-control`(4px)。順位バッジは円(`rounded-full`)。それ以外は 0。pill(999px)は使わない。
- **影は使わない**: `shadow-rn(-soft)` は移行期のヘアラインリング。新規UIでは使わず `border-rn-border` を書く。
- **浮かせない**: hover は色の僅差(背景 `--surface-soft`、枠 `--text`)か下線だけ。`translate` `scale` 禁止。

## 4. タイポグラフィ

- フォント: Noto Sans JP のみ(400 / 500 / 700)。`font-feature-settings: "palt"` を `:root` で有効化済み。
- サイズ階層(これ以外を増やさない):
  - h1 `38px/1.4/700`(選手名のみ 40px) / セクション・記事 h2 `24px/1.5/700` / 一覧見出し `18px/700` / カード表題 `24px/1.45/700`
  - リード `17px/1.95` / 本文 `16px/1.95` / UI `14px` / 表 `14px`(密な2列表 13px) / メタ・ラベル・注記 `13px` / 表ヘッダ・小ラベル `12px` / 図ラベル `11px`
- ウェイトは **400 / 500 / 700 の3段だけ**。600・800 は使わない。
- 見出しは内容を名詞句で言い切る。アクセント棒・下線・左ボーダーは付けない。
- 数値(タイム・順位・件数・日付)は `[font-variant-numeric:tabular-nums]`。
- named `text-sm` 等は line-height を束ねるため使わず、`text-[13px]` + `leading-[…]` で指定。

## 5. スペーシング

4pxグリッド。使用可能なステップ: 4 / 6 / 8 / 10 / 12 / 14 / 16 / 20 / 24 / 32 / 40 / 48 / 56 / 64。
- 版面: コンテナ 1200px(左右 40px、モバイル 20px)。記事・大会・選手の一段組は 760px。
- セクション間 48〜64 / 記事 h2 の上 `2.4em` / 一覧の行 `py-3.5`。
- 階層は「箱」ではなく余白と見出しで作る。同じ重さの箱を3つ以上並べない(箱自体を作らない)。

## 6. コンポーネント規定(実装の単一ソース)

スタイルは以下のモジュールに集約されている。**JSXに生のarbitrary値を直接書き足す前に、まず該当モジュールへ**:

| 領域 | モジュール |
|---|---|
| ボタン | `frontend/components/ui/button-classes.ts`(Button / ButtonLink) |
| 検索UI | `frontend/components/search/search-classes.ts`(`sx`) |
| 静的LP | `frontend/components/lp/lp-classes.ts` |
| 記事 | `frontend/components/article/article-classes.ts` |
| 結果・順位バッジ | `frontend/components/results/results-classes.ts`(`rankBadgeClass` は検索ページと共用) |
| ホーム | `frontend/app/page.tsx` 冒頭の定数 |

規定値:
- **ボタン**: 高さ40(小型34)、radius 4、primary=墨地 `rn-text` に白文字(1画面1つ) / secondary=白地+1px墨枠+墨文字。hover は背景の僅差のみ。
- **入力・select**: 1px `border-rn-border`、白地、radius 4、高さ40、`focus-visible:outline-2 focus-visible:outline-rn-primary`。
- **表**: 上罫線1px墨(`thead th`)、ヘッダ 12px `rn-meta` 500 地なし、行罫線 `rn-border`、14px、数値列は右寄せ+tabular-nums。行hoverの地色なし。モバイル(≤640)は data-label 付きの積み(角丸0)。
- **セグメント**(すべて/男子/女子): 角丸0、選択=墨地白文字、非選択=1px `rn-border` 枠。
- **チップ**(絞り込み条件): 1px枠、radius 2、12px。pill にしない。
- **順位バッジ**: 直径26の円、12px/700。1位=青地白文字 / 2〜3位=灰青地 `rn-primary-soft` 墨文字 / 4位以下=`rn-surface-soft` 地 `rn-muted` 文字。金銀銅は廃止。
- **図**(横棒・セル・順位の推移): 主色 `rn-primary`、副色 `rn-primary-soft`、トラック `rn-surface-soft`、ラベル `rn-meta` 11〜12px、棒は角丸0。図題 16px/700、説明 13px `rn-meta`、上罫線墨。Recharts も同じ値(グリッド `#eef1f5`、ツールチップ角丸0・1px枠・影なし)。
- **空状態**: 上罫線+1文+リンク1つ。破線の箱は使わない。
- **一覧(記事・大会)**: 箱にせず下罫線の行。表題 24px / 本文 14px `rn-muted` / 日付 13px `rn-meta` を右下。
- **次の大会(ホームの帯)**: 見出し行の下に、上罫線(墨)で区切った1行。ラベル(次の大会 / 開催中 / 結果を収録中)14px/700 + 大会名 14px/500 + 日程・会場 `rn-meta` + リンク1つ。日程は `frontend/data/schedule.json`(JARA から手で転記)、判定は `lib/schedule.ts`(開催中 > 終了して収録前 > 90日以内の次)。静的ビルドなのでカウントダウンは出さない。

## 7. アクセシビリティ

- 文字コントラストAA(4.5:1)。新色は必ず検証。
- インタラクティブ要素にフォーカスリング必須。`aria-expanded` / `aria-controls` / `role` は既存実装(詳細条件・コンボボックス)の水準を保つ。
- アニメーションには `motion-reduce:` 対応を必ず併記。
- タップ領域はモバイルで40px以上(`max-[768px]:min-h-10` 等)。

---

## 8. 禁止事項(ダサさの再発防止)

1. 全面色付き背景・背景グラデーション
2. 影(常時・hover とも)。浮かせる hover
3. pill(999px)。円は順位バッジだけ
4. 装飾グラデーション(ボタン・見出し下線・棒グラフ含む)、見出しのアクセント棒・左ボーダー
5. 新規の枠線色・文字色の場当たり追加。青をボタンや見出しに使う
6. 箱(カード・パネル)。「箱の中に箱」のネスト、同重量の箱の羅列
7. 12px未満の本文(図のラベルを除く)、600・800 のウェイト、金銀銅のメダル色、絵文字

## 9. AIっぽさのアンチパターン(自己点検用)

生成UIに出やすい癖の一覧。UIを新規作成・変更したら、提示する前に下の手順で突き合わせる。
代替はすべて §2〜§6 のトークン・寸法に紐付ける(新しい色・radius・サイズを作らない)。

| # | 癖 | このサイトでの代替 |
|---|---|---|
| 1 | **ヒーロー+3カード+CTAの定型**。どのページも同じ骨格 | 骨格はページの役割で決める: ホームは記事3列(箱ではなく下罫線の列)+2列リスト、検索 `/search` は情報密度重視、記事・大会・選手は 760px の一段組(§5)。CTA(primary ボタン)は1画面1つ(§6) |
| 2 | **全要素に角丸と影**。テキストや表まで浮いたカードに入れる | 箱を作らない(§3)。radius は入力・ボタンの 4px と順位バッジの円だけ。影なし。表・リスト・本文はヘアライン(`--border` 1px)と余白で区切る |
| 3 | **青紫グラデ・光彩・ガラス風**(blur、半透明の面) | グラデ禁止(§3)。面は作らない。青 `--primary` は図・1位・選択状態だけに使い、ボタン・見出し・リンクは墨色(§2)。装飾は置かない |
| 4 | **絵文字アイコン**、意味のない装飾アイコン | 絵文字は使わない。アイコンは `SiteHeader.tsx` と同じインラインSVG(`stroke="currentColor"`、22px / 補助10px)で、意味を持たないものは置かない。順位は §6 の順位バッジ(青・灰青・薄灰)で表す。金銀銅・🥇は使わない |
| 5 | **中央揃えの連発**。見出し・本文・カードの中身まで中央 | 基本は左揃え(`.lp-hero` の見出し・リードも左)。中央揃えは空状態(`EmptyState`)、単点表示、表の年・順位列に限る |
| 6 | **均一な余白**。すべて同じ gap / padding で階層がない | 4pxグリッドの中で階層ごとに差をつける: セクション間32 / カード内8〜12 / カードpadding 14〜24(§5)。見出し直後は詰め、セクション前は空ける(記事h2は `margin-top: 2.4em`) |
| 7 | **コピー調の見出し**。「〜を、もっと自由に。」「次世代の〜」、体言止めと感嘆符の連発 | 見出しは内容を名詞句で言い切る(例:「2026年の主要大会」「団体別の成績」)。記事タイトルは大会名+年+何がわかるか。UI文言はSmartHRトーン(参照基準)。「究極」「シームレス」「革新的」の類は使わない |
| 8 | **和欧混植・行長を考えない本文**。1行が長すぎる、英数字が本文フォントのまま、見出しの変な位置で折り返し | フォントは Inter + Noto Sans JP、数値は `tabular-nums`(§4)。行長は全角35〜40字相当: リード `max-width: 60ch`(`.lp-lead`)、サブタイトル62ch、記事本文は820px・行間1.95。見出しの折り返しは `lp-h1-line` で文節境界に限定。英大文字ラベルは11pxの用途(§4)にだけ使う |
| 9 | **説明過多**。各カードに1行の説明文、「〜できます」の案内、ツールチップ頼み | 1ラベル+1値を基本にする。補足は `--muted` 13px 1行まで(§4)。操作の説明は空状態の1アクション(§6)で代える |
| 10 | **ダミー数値と汎用プレースホルダー**。「99%」「10,000+ users」「Lorem ipsum」 | 実データのみ。件数・タイムは `tabular-nums`。値が無いときは §6 の空状態 |
| 11 | **ボタンの乱立**。全幅の大型ボタン、primaryが複数、pillボタン | §6 ボタン規定: 高さ40 / radius 4。primary(墨地白文字)は1画面1つ、他は secondary(白地+墨枠)かテキストリンク。pill は使わない(§3) |
| 12 | **大げさなホバー**。拡大(scale)、300ms超の遷移、色が別物に変わる | 浮かせない。hover は下線か背景 `--surface-soft`、枠 `--text` の僅差だけ(§3)。`motion-reduce:` を必ず併記 |

### 自己点検手順(UIを作った後、提示する前)

1. 内蔵ブラウザで dev サーバーを開く(`preview_start` の `frontend-dev`。設定は `.claude/launch.json`)。該当ページへ移動する。
2. desktop(`resize_window` preset `desktop`、1280px 相当)でスクリーンショットを撮る。
3. mobile(`resize_window` preset `mobile` = 375px)でスクリーンショットを撮る。終わったら preset `desktop` に戻す。
4. 2枚を上の一覧と番号順に突き合わせ、該当箇所を書き出す(「該当なし」も明記する)。
5. 該当箇所を直し、再度スクリーンショットで確認してから提示する。提示時に「点検した番号 / 直した番号」を添える。
6. 寸法・色の裏取りは computed style(`getComputedStyle`)の実測で行う(Preflight が効かないため見た目だけで判断しない)。
